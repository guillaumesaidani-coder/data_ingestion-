01 — Problème

Pourquoi le réseau exige une taille d'entrée fixe

Un auto-encodeur CNN empile des couches de convolution, chacune avec un nombre de filtres et de connexions figé à la compilation. Changer la taille de l'image en entrée modifierait le nombre de valeurs à traiter par chaque couche — le réseau doit recevoir exactement la même forme à chaque fois.

Pour le dataset bottle, les images originales font 900×900 px. On les ramène à 256×256 px, soit un facteur de réduction ÷7. Chaque pixel de sortie "représente" un carré de ~7×7 pixels de l'original.

02 — Stratégie

Stretch vs Padding : préserver le ratio

Quand l'image source n'est pas carrée, deux approches s'opposent. La déformation (stretch) remplit exactement la cible mais écrase les proportions. Le padding (letterbox) préserve le ratio et complète avec des pixels noirs.

Cas MVTec bottle : les images sont carrées (900×900), donc stretch = padding. Le padding devient critique pour des catégories non-carrées comme zipper ou wood — où une bouteille "écrasée" aurait un profil différent de ce que le modèle a appris.
03 — Interpolation

Comment calculer la valeur d'un pixel redimensionné ?

Lors d'une réduction 900→256, chaque pixel de sortie est calculé à partir d'un voisinage de pixels sources. La méthode d'interpolation définit combien de voisins sont pris en compte et avec quel poids.

NEAREST
1 pixel voisin
⚡⚡⚡⚡⚡   ★☆☆☆☆
Pixel le plus proche — aucune interpolation. Résultat pixellisé, effet "blocs" visible.
Rapide — pauvre
BILINEAR
4 pixels voisins
⚡⚡⚡⚡   ★★★☆☆
Moyenne pondérée linéaire 2D. Résultat lissé, transitions douces. Légèrement flou.
Bon compromis
BICUBIC
16 pixels voisins
⚡⚡⚡   ★★★★☆
Interpolation cubique — préserve mieux les bords. Peut générer de légères oscillations.
Bon pour réduction
LANCZOS
Filtre sinc (noyau ~8px)
⚡⚡   ★★★★★
Filtre optimal pour la réduction — minimise l'aliasing et préserve les bords nets. Idéal pour ÷7.
✓ Retenu pour TP
Règle de choix
Pour une réduction importante (÷4 ou plus), LANCZOS est systématiquement le meilleur choix. Pour un agrandissement, BICUBIC donne de meilleurs résultats. NEAREST est réservé aux masques binaires (labels) où toute interpolation de couleur serait fausse. 
from PIL import Image

# Pour les images : LANCZOS (meilleure qualité à la réduction)
img_resized = img.resize((256, 256), Image.LANCZOS)

# Pour les masques GT : NEAREST (pas d'interpolation → labels binaires préservés)
mask_resized = mask.resize((256, 256), Image.NEAREST)
04 — Résolution

Quelle résolution minimale pour détecter les défauts ?

Réduire la résolution compresse l'information. En dessous d'un certain seuil, le défaut — quelques pixels dans l'image redimensionnée — disparaît dans le bruit de l'interpolation.

Choix pédagogique
256×256 est le compromis retenu pour ce TP : défaut visible, réseau 8× plus compact qu'en 256×256, entraînement rapide sur CPU. En production industrielle, 256×256 serait préférable pour les défauts fins (contamination de surface).

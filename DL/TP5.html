§0 Pourquoi l'explicabilité ?

En TP3 et TP4, on a optimisé la performance (AUROC, rappel). Mais en contexte industriel, un opérateur humain doit pouvoir valider ou rejeter la décision du système. Pour cela, il lui faut une réponse à la question :

Question production : « Pourquoi ce flacon est-il signalé défectueux ? Quelle zone visuelle déclenche l'alarme ? »

SHAP (SHapley Additive exPlanations) répond à cette question en calculant la contribution marginale de chaque feature (pixel, superpixel, métrique) sur le score final — avec une garantie théorique d'unicité issue de la théorie des jeux coopératifs.

Valeur de Shapley — intuition

Imaginons que chaque pixel soit un joueur dans un jeu où le score d'anomalie est le gain. La valeur de Shapley de chaque joueur est sa contribution équitable au gain, moyennée sur toutes les coalitions possibles :

φi(f) = Σ |S|! × (|N| − |S| − 1)! |N|! × [ f(S ∪ {i}) − f(S) ]

S = coalition de features, N = ensemble de toutes les features, f(S) = prédiction du modèle avec seulement les features de S.

§1 SHAP Gradient — attribution pixel par pixel (auto-encodeur)

L'auto-encodeur produit un score MSE(image, reconstruction). Pour l'expliquer, on crée un scorer_model qui expose ce scalaire comme sortie :

# scorer_model : AE → MSE scalaire
inp_s   = keras.Input(shape=(256, 256, 3))
recon_s = model_v3(inp_s)
score_s = Lambda(
    lambda t: tf.expand_dims(
        tf.reduce_mean(tf.square(t[0] - t[1]), axis=[1,2,3]), axis=1
    )
)([inp_s, recon_s])
scorer_model = keras.Model(inp_s, score_s)

# GradientExplainer : fond = 50 images saines de validation
explainer = shap.GradientExplainer(scorer_model, background)
shap_vals = explainer.shap_values(imgs_defect)
# → liste de 1 array (N, 256, 256, 3)
Expected Gradients : approximation différentiable de SHAP. Pour chaque pixel, intègre le gradient ∂score/∂pixel entre le fond aléatoire et l'image cible. Équivalent à des Integrated Gradients avec fond stochastique.

Lecture de la carte SHAP

CouleurSignification
rouge Ce pixel augmente le score d'anomalie
bleu Ce pixel diminue le score d'anomalie
|valeur| grande Pixel très influent — positif ou négatif

On agrège sur les 3 canaux RGB pour obtenir une carte 2D : |shap_vals[0]|.sum(axis=-1) → (N, 256, 256).

§2 Comparaison : carte d'erreur vs carte SHAP

Les deux cartes répondent à des questions différentes :

Carte d'erreur de reconstruction

  • Espace OUTPUT (décodeur)
  • Où le décodeur s'est trompé
  • Mesure : (img − recon)² par pixel
  • Rapide — 1 forward pass
  • Ne distingue pas cause/effet

Carte SHAP

  • Espace INPUT (encodeur)
  • Quels pixels causent le score élevé
  • Mesure : contribution marginale de chaque pixel
  • Coûteux — N forward passes × fond
  • Garantie théorique d'additivité
Divergence possible : un pixel défectueux peut être partiellement masqué par le décodeur (faible erreur output) mais avoir une forte attribution SHAP (input très influent). Les deux vues sont complémentaires.
§3 SHAP Partition — superpixels sur PatchCore

PatchCore est non-différentiable (kNN, pas de gradient). On utilise PartitionExplainer, activé automatiquement par shap.Explainer avec un masker image.

Masker et inpainting

Pour évaluer f(S) (score sans les features de S), les pixels masqués sont remplacés par inpainting "inpaint_telea" — algorithme de propagation de texture — plutôt que par une couleur unie qui créerait une distribution hors domaine.

def patchcore_scorer(imgs):  # (n, 256, 256, 3) → (n,)
    feats = feat_model(tf.cast(imgs, tf.float32), training=False).numpy()
    return np.array([
        float(nn_pc.kneighbors(f.reshape(-1, 512))[0].max())
        for f in feats
    ])

masker     = shap.maskers.Image("inpaint_telea", shape=(256,256,3))
explainer  = shap.Explainer(patchcore_scorer, masker)
shap_vals  = explainer(imgs_pc, max_evals=500, batch_size=50)
# shap_vals.values : (n, 256, 256, 3)
max_evals=500 : nombre d'évaluations du scorer par image. Plus de valeurs → meilleure approximation, mais ≈ 2–4 min par image. Chaque évaluation fait un forward pass du backbone ResNet50 entier.

Lecture des superpixels

Les superpixels rouges sont les régions qui augmentent la distance kNN (donc le score d'anomalie). Ils correspondent généralement aux zones dont les features s'écartent le plus de la banque mémoire normale.

Lecture du beeswarm

  • Axe X : valeur SHAP → à gauche = diminue le score défaut, à droite = l'augmente
  • Axe Y : features triées par importance décroissante (|SHAP| moyen)
  • Couleur des points : valeur brute de la feature (bleu = faible, rouge = élevée)

Observation : les points roses (valeur élevée) de patchcore_score et max_error sont tous à droite → un score PatchCore ou une erreur max élevés augmentent systématiquement la probabilité de défaut.

§5 Limites de l'explicabilité SHAP
LimiteExplicationAtténuation
Coût calcul GradientExplainer ≈ N_bg × N_images forward passes ; PartitionExplainer ≈ 500 passes / image Batch processing, GPU, max_evals limité
Corrélation ≠ causalité SHAP mesure des contributions marginales, pas des relations causales Compléter avec tests d'intervention (masking réel)
Dépendance au fond GradientExplainer est sensible au choix du background (ici : 50 images de validation) Tester plusieurs backgrounds, vérifier la stabilité
Mauvais modèle → mauvais SHAP Si le modèle a un AUROC faible, SHAP explique un mauvais modèle Toujours vérifier la performance avant l'explicabilité
Features corrélées mse_score et mean_error sont quasi identiques → SHAP les discrimine parfois arbitrairement Réduire la base de features, vérifier les corrélations

Conclusion

L'explicabilité est complémentaire à la performance, non substituable. En production, la bonne pratique est de combiner :

  1. Une métrique de performance validée (AUROC ≥ 0.85 → PatchCore)
  2. Une carte de localisation (superpixels SHAP ou heatmap)
  3. Un score de confiance affiché à l'opérateur (distance brute)

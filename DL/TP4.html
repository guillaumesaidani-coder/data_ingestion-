00 — Rappel du problème

Pourquoi le TP3 a échoué

Diagnostic TP3 — AUROC = 0.465 (pire que le hasard)

Cause racine : ratio de compression ≈ 1.5. Le goulot (32×32×128 = 131 072 valeurs) est trop proche de l'entrée (256×256×3 = 196 608 valeurs). Le modèle a appris une quasi-identité : il reconstruit les défauts aussi fidèlement que les pièces saines, éliminant tout signal d'anomalie.

FN = 53/63 défauts manqués. Inverser le seuil donnerait AUROC = 0.535 — toujours médiocre.

Ce TP corrige les trois causes structurelles :

  • §1 — Goulot trop large → le resserrer (ratio ≥ 4)
  • §2 — MSE insensible aux textures → ajouter SSIM
  • §3 — Entraînement from scratch → utiliser un backbone pré-entraîné
01 — Amélioration 1

Goulot d'étranglement resserré

On ajoute une 4e couche Conv2D dans l'encodeur (filters=(32, 64, 128, 64)). Le goulot passe de 32×32×128 à 16×16×64.

1.5×

12×

# TP3 baseline — ratio ≈ 1.5
model_v1 = build_autoencoder(filters=(32, 64, 128))

# TP4 amélioré — ratio ≈ 12
model_v2 = build_autoencoder(filters=(32, 64, 128, 64))
print(compression_ratio(model_v2))  # → 12.0
Pourquoi le ratio 12 ?

Un ratio ≥ 4 force le modèle à encoder uniquement les structures récurrentes dans les images saines — pas les détails uniques comme les défauts. Mais un ratio trop élevé (> 20) peut dégrader aussi la reconstruction des images saines, augmentant la val_loss de référence.

02 — Amélioration 2

Perte MSE + SSIM

Même architecture (ratio ≈ 12), perte 0.8 × MSE + 0.2 × (1 − SSIM).

MSE seul

Compare les valeurs absolues pixel par pixel. Dominé par les grandes zones homogènes (fond noir). Insensible aux petites différences de texture ou de bord.

+ SSIM

Compare la structure locale : luminance, contraste, corrélation de patches 11×11. Beaucoup plus sensible aux défauts fins de texture et aux crack.

from indusense.vision.model import mse_ssim_loss

loss_fn = mse_ssim_loss(alpha=0.8)   # 80% MSE + 20% (1−SSIM)
history = ae_train(model_v2, X_train, X_val, loss=loss_fn, ...)
03 — Amélioration 3

PatchCore-lite — backbone pré-entraîné

PatchCore résout le problème d'identité par construction : au lieu de reconstruire des pixels, on compare des représentations extraites par un réseau pré-entraîné sur ImageNet qui n'a jamais vu de bouteilles.

1
Backbone ResNet50 → features patches

On coupe ResNet50 à une couche intermédiaire (conv3_block4_out). Chaque image 256×256 produit une grille de patches 32×32, chacun décrit par un vecteur de 512 features.

2
Banque mémoire (coreset)

On extrait les features de toutes les images saines d'entraînement → 168 × 1024 = ~172 000 patches. On sous-échantillonne à ~17 000 (coreset 10%) pour limiter la mémoire.

3
Score = distance max au voisin le plus proche

Pour chaque image test, on calcule la distance de chaque patch au voisin le plus proche dans la banque mémoire. Le score image = max sur tous les patches. Une distance élevée = patch sans équivalent dans les images saines = anomalie.

Avantage clé vs auto-encodeur

Le backbone a appris à représenter les structures visuelles générales (ImageNet, 1.2M images). Il encode les textures, les bords, les formes — pas à reconstruire des bouteilles spécifiques. Un défaut produit nécessairement un vecteur feature différent des patches sains : pas de risque d'identité.

from tensorflow.keras.applications import ResNet50
from sklearn.neighbors import NearestNeighbors

# Backbone — pas d'entraînement
base = ResNet50(include_top=False, input_shape=(256,256,3), weights="imagenet")
feat_model = keras.Model(base.input, base.get_layer("conv3_block4_out").output)

# Banque mémoire (coreset 10%)
feats  = feat_model.predict(X_train)          # (168, 32, 32, 512)
patches = feats.reshape(-1, 512)              # (172032, 512)
idx    = rng.choice(len(patches), size=len(patches)//10)
nn     = NearestNeighbors(n_neighbors=1).fit(patches[idx])

# Score = max distance sur les patches de l'image
dists, _ = nn.kneighbors(img_patches)
score = dists.max()

Comparaison des quatre approches

Lecture des résultats

  • §1 (ratio 12, MSE) : AUROC 0.465 → 0.527. Amélioration modeste — resserrer le goulot aide mais ne suffit pas seul. L'encodeur compresse mieux mais la perte MSE reste aveugle aux textures.
  • §2 (ratio 12, MSE+SSIM) : AUROC 0.618. Le SSIM apporte un gain supplémentaire (+0.09) grâce à la sensibilité structurelle locale, malgré un rappel légèrement inférieur à §1 (seuil à recalibrer).
  • §3 PatchCore-lite : AUROC 0.859, FN réduit de 53 → 20. Bond de +0.24 par rapport à §2 — sans aucun entraînement. Confirme la supériorité des features pré-entraînées sur la reconstruction from scratch.

Conclusion

L'auto-encodeur de reconstruction est un excellent support pédagogique : il force à comprendre la compression, le goulot, la perte et le seuil. Mais il atteint ses limites structurelles en production. Les méthodes feature-based (PatchCore, PaDiM) résolvent le problème d'identité par construction et dominent MVTec AD avec peu ou pas d'entraînement.

Pourquoi label_failure_next_24h ?

Le gold dataset expose 4 labels binaires — panne dans les 6h, 12h, 24h ou 48h suivantes. Ils sont imbriqués : une panne à 6h déclenche aussi les 3 autres. Choisir le bon horizon conditionne la qualité d'apprentissage et l'actionnabilité terrain.

Équilibre optimal : les features _prev_24h et _rolling_24h du gold dataset sont construites sur la même fenêtre, ce qui aligne le signal télémetrique sur la cible. Un taux de positifs de 3.6 % (scale_pos_weight ≈ 28) est assez rare pour être prédictif, assez fréquent pour entraîner le modèle. Avec 24h de marge, l'équipe maintenance peut planifier l'intervention dans le quart de travail suivant — ce qui n'est pas possible à 6h ou 12h en organisation standard.

Conséquence directe sur la modélisation Ratio de coût FN / FP ≈ 33×. Un FN coûte autant que 33 FP. On doit donc optimiser le Recall (minimiser les pannes manquées) plutôt que la Precision ou l'Accuracy. La métrique pivot est le PR-AUC — non biaisée par le déséquilibre de classes (3.6 % positifs). En production, le seuil de décision sera abaissé bien en dessous de 0.5.

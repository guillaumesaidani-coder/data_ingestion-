Concept — Pré-calcul sur historique complet

La correction clé vs TP10 : les µ et σ sont calculés sur la totalité du dataset, avant tout split. La machine de validation a toujours ses statistiques propres disponibles.

TP10 vs TP12 — Où sont calculées les statistiques machine ?
# TP12 — stats calculées sur df_full (historique complet machine)
def compute_machine_zscores(df_full, raw_cols, suffix="_zmachine"):
    machine_stats = df_full.groupby("machine_id")[raw_cols].agg(["mean", "std"])
    # Toute machine a ses propres µ/σ — pas de fallback flotte nécessaire
    for col in raw_cols:
        mu  = df_full["machine_id"].map(machine_stats[col]["mean"])
        sig = df_full["machine_id"].map(machine_stats[col]["std"]).replace(0, 1)
        result[f"{col}{suffix}"] = (df_full[col] - mu) / sig

05

Règle générale

Principe retenu — TP12

Pré-calculer les z-scores machine sur l'historique complet est la bonne approche pour éviter le domain shift de TP10. Mais empiler les zscore sur les raw sans re-tuner les HP introduit une redondance structurelle. La stratégie correcte est de remplacer les raw par leurs équivalents zmachine (N features stables → HP réutilisables), ou de re-tuner Optuna sur l'espace augmenté. Doubler le feature set sans adapter colsample_bytree revient à exposer deux fois plus de features corrélées par arbre — le modèle ne peut pas en tirer parti.

TP2

Anti-fuite temporelle

TP 2 features/temporal.py

Le problème résolu — pour prédire une panne future, un modèle ne doit apprendre qu'à partir de données passées. Si une feature d'entraînement contient, même involontairement, une info du futur ou la valeur courante au temps t, le modèle « triche » à l'entraînement — score excellent — puis s'effondre en production, où cette info n'existe pas encore au moment de prédire.

Tri — df.sort_values([machine, timestamp]) avant tout groupby().shift(). Sans lui, shift(1) récupérerait la ligne juste au-dessus dans le tableau — qui peut appartenir à une autre machine, ou être dans le désordre chronologique — pas la vraie valeur précédente.

Ordre des opérations — series.shift(1).rolling(window).mean() calcule la moyenne des N valeurs précédentes, en excluant la valeur courante. Inverser l'ordre (rolling puis shift) ferait entrer la valeur du temps t dans le calcul de sa propre moyenne — fuite.

L'exercice — lire le fichier, comprendre ces deux points, puis rejouer la suite anti-fuite qui vérifie noir sur blanc ces garanties (ex. la première ligne d'un lag doit être NaN, faute de passé disponible en début de série).

Fuite de données — une info du futur qui entre dans l'entraînement produit un score faussement excellent. Un score trop beau doit inquiéter.

TP3

Normalisation des identifiants machine

TP 3 normalize_machine_id

Le problème résolu — les données arrivent de sources différentes (CSV température, TSV pression, dump SQL des machines) qui n'écrivent pas l'identifiant machine de la même façon. Sans normalisation, la jointure entre ces sources (merge_asof dans build_dataset) ne reconnaîtrait pas que MACH-01 et MACH_01 désignent la même machine — les données se retrouveraient mal appariées, silencieusement.

Ce que fait la fonction — extrait le premier nombre trouvé dans la chaîne brute, quel que soit le séparateur (- ou _), et le reformate toujours en MACH-0N (2 chiffres) :

MACH-01 → MACH-01 MACH_01 → MACH-01 M-06 → MACH-06 M-2 → MACH-02

Repères

À ne pas oublier

Package
Un dossier importable — src/indusense/ devient import indusense.
Module
Un fichier .py pris individuellement — un package en contient généralement plusieurs. À ne pas confondre avec « module 23 », le nom de cette unité de formation.
Refactoring
Réorganiser le code sans changer son comportement observable.
Layout src/
Les tests s'exécutent contre le package installé, comme en production — les erreurs de packaging sont détectées tôt.
uv plutôt que pip
Plus rapide, et un uv.lock qui fige les versions exactes pour des environnements identiques partout.

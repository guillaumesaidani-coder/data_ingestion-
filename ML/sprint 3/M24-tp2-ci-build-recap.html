Job build : compiler et publier le wheel

La CI ne fait pas que vérifier le code — elle peut aussi fabriquer le livrable final et le rendre téléchargeable, sans jamais quitter GitHub.

TP validé — wheel construit localement jalon 02 · branche guillaume-saidani

Pourquoi

Deux jobs, deux responsabilités

.github/workflows/ci.yml n'avait qu'un job, quality : installer, lint, formater, tester. Ce TP en ajoute un second, build, dont le seul rôle est de fabriquer le paquet installable (le wheel) et de le rendre disponible en téléchargement depuis le run GitHub Actions.

Séparer les deux sert un objectif précis : ne jamais construire un livrable à partir d'un code qui n'a pas passé les vérifications. C'est ce que fait la clé needs: quality :

quality → si vert → build → wheel téléchargeable
Fail fast. Si quality échoue, build ne démarre même pas — pas de calcul gaspillé à empaqueter un code cassé.

Étape par étape

Ce que fait chaque ligne du job build

  1. 1needs: quality — attend que le job quality se termine avec succès avant de démarrer.
  2. 2actions/checkout@v4 — récupère le code du dépôt sur cette nouvelle VM (chaque job a sa propre machine jetable, même dans le même run).
  3. 3astral-sh/setup-uv@v3 — installe uv, sans repasser par setup-python : uv build gère lui-même l'environnement de build.
  4. 4uv build — lit pyproject.toml, produit une distribution source (.tar.gz) et un wheel (.whl) dans dist/.
  5. 5actions/upload-artifact@v4 — copie dist/*.whl hors de la VM jetable avant qu'elle ne soit détruite, sous le nom indusense-wheel, téléchargeable depuis la page du run.

Vérification locale

Rejouer ce que ferait la CI

Avant de compter sur GitHub Actions, on reproduit l'étape critique en local — si uv build échoue sur ta machine, il échouera aussi sur la VM Ubuntu :

uv build
Building source distribution...
Building wheel from source distribution...
Successfully built dist\indusense_sprint3_starter-0.1.0.tar.gz
Successfully built dist\indusense_sprint3_starter-0.1.0-py3-none-any.whl

Le fichier produit correspond exactement au motif dist/*.whl attendu par l'étape Upload artifact. dist/ reste listé dans .gitignore — ce build local ne pollue pas git status, aucun nettoyage à faire.

Repères

Vocabulaire du job

Wheel (.whl)
Le format binaire installable par pip/uv — ce que reçoit un utilisateur final du package, sans avoir besoin des sources.
Source distribution (.tar.gz)
Une archive du code source du package, à partir de laquelle un wheel peut être reconstruit.
Artifact GitHub Actions
Un fichier produit pendant un run, conservé et téléchargeable depuis la page de ce run — distinct des artefacts métier du projet (artifacts/models/).
needs:
Déclare une dépendance entre jobs — le job qui la porte attend que tous les jobs listés se terminent en succès.

Orchestration Prefect — pipeline InduSense

Un seul @flow, quatre @task séquentielles : ingestion → modèle → scoring → écriture. Ce que Prefect ajoute n'est pas l'enchaînement (un script ferait pareil) mais la reprise — cache par empreinte de fichiers, modèle réutilisé s'il existe déjà, écriture idempotente.

Détail par tâche

TaskRôleEntréeSortieMécanisme Prefect / reprise
build-gold-dataset ingestion + jointure + features temporelles 3 fichiers data_dir DataFrame gold cache_key_fn = SHA-256(mtime+taille des 3 fichiers, window_hours) · persist_result=True · retries=1
ensure-model entraîne, ou réutilise si déjà présent dataset, model_dir chemin rf.joblib reprise applicative : skip si model_path existe et retrain=False · retries=1
predict-latest score la dernière observation par machine dataset, model_path DataFrame predictions —
store-predictions upsert des scores predictions, db_url nb de lignes en base INSERT ... ON CONFLICT DO UPDATE — rejouer le flow met à jour, ne duplique pas
Nom du run : flow_run_name est généré dynamiquement (indusense-pipeline-<data_dir>-<horodatage>) — chaque exécution est traçable individuellement dans Prefect. Les deux points d'entrée appellent la même fonction indusense_pipeline() : aucune logique dupliquée entre la preuve locale (jalon 07) et l'exécution empaquetée (module 30).
